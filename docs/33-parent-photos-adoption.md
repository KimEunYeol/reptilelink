## 원본과 모델

## 저장·실패·현재 공개

부모 예약/취소는 자식·역할·요청 UUID를 함께 검증하는 별도 사용자 RPC다. 알 수 없는 예약 취소도 같은 UUID의 tombstone으로 뒤늦은 예약을 막는다. Worker는 사용자 RPC 확인 뒤 기존 방식으로 create-only 업로드 URL/임대를 제공하고 실제 두 WebP의 MIME·크기·해상도·SHA를 확인한다. 관리자 권한으로 사용자의 저장 검증을 우회하지 않는다.

새 등록창도 원본340px 팝업·부분 기본자산·성별/가로 입력 행/저장·취소를 사용한다. 기존 자기사진 다중 선택·대표 선택은 유지하고 부/모 두 칸을 따로 제공한다. 먼저 비공개 생성→파일 준비→사진/일반필드 연결→선택한 공개 상태→실제 조회 확인 순서다. Storage와 DB의 여러 단계가 하나의 외부 트랜잭션이라고 주장하지 않는다. 중간 실패/충돌로 이미 등록된 항목은 지우지 않으며 현재 목록을 확인해 기존 편집에서 이어갈 수 있다.

등록/수정의 미확인 명령은 입력/이동을 보호하고 업로드 재할당보다 같은 저장 요청 확인을 우선한다. 최신 값/사진은 명시적으로 검토하며 오래된 자산이 초안에 남으면 최신 사진 선택을 요구한다. 확정된 생성 거절 후에는 실제 목록 확인과 사용자의 새 요청 준비 선택으로 날짜/로컬 파일을 유지한다.24h 단조·벽시계 만료 후에는 오래된 UUID를 재전송하지 않고 현재 값을 확인한다. 취소도 미확인 명령과 실제 저장값을 확인한 뒤 연결되지 않은 자기 준비 파일만 정리한다.

연결된 부/모는 일반 취소/정리로 제거할 수 없다. 교체/삭제는 참조를 해제하고 이전 파일을 삭제 대기로 보내며, 개체 삭제/탈퇴도 부모 참조를 먼저 해제한다. 기존 삭제대기 개체의 불가역 guard는 유지한다. 실제 파일이 남거나 업로드 유효기간이 끝나지 않았으면 예산을 반환하지 않는다. 만료/정리 대기는 기존 로컬 운영 정리 명령과 이후51~53의 진단/인계를 따른다.

공개 React/Worker는 같은 두 부모 영역·입양일 행을 실제 값으로 제공한다. 두 사진 모두 없으면 부모 영역을 생략하고, 미입력 날짜는 미입력으로 표시한다. 공개 DTO/이미지는 현재 활성·프로필/자식 공개·미삭제·같은 역할/ready 조건을 확인한다. 원본 테이블·역할/경로·소유자 AuthID·비공개 메모를 공개하지 않는다. JS 없는 상세에서도 사진·날짜와 실제 닫기/로그인 링크를 읽는다.

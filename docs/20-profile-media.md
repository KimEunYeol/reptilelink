# 프로필·배경 이미지와 테마 (#24)

F-02의 프로필/배경 파일을 기존 텍스트·SNS 폼의 한 번의 적용에 연결했다. 적용 전 파일 선택은 탭 메모리/Blob 미리보기이며, 업로드를 시작하지 않고 취소하면 서버 쓰기가 없다. 새 파일은 업로드·실제 검증을 완료한 뒤 기존 파일과 한 트랜잭션으로 교체한다. 적용된 변경은 공개 중인 페이지에 바로 반영된다.

## 원본과 화면

전체 보드 디자인 수정 열(x1950~3150,y1200~5600)과 공통 PC 안내(x0~3900,y8270~9270), `마이페이지-디자인수정.png`/`-m.png`, `링크페이지.png`/`-m.png`를 기준으로 한다. 원형 프로필·등록/삭제·자동 조정 안내 → 소개/이름/설명 →450:276 배경·등록/삭제 → SNS/하단 단일 적용의 순서를 따른다. 공개 커버의 오른쪽에 둥근 아바타가 겹치고 그 아래에 실제 소개를 표시한다. 기존 임의 영어 커버와 해당 영역의 Gecko/Sprout을 제거했다.

작은 기본 이미지 두 개만 원본에서 추출했다. 출처/좌표/SHA는 `public/brand/profile/source.json`에 있다. 기본 커버는 원본의 녹색 면과 기존 제공 워드마크를 재사용한다. 테마 독립 화면은 없으므로 기존 원형 팔레트/선택 체크 패턴으로만 확장했다. green은 설정 원본의 실제 픽셀#31ba51, mint는 링크 팔레트#8cd58f, forest는 공개 원본 아바타의 실제 반복 픽셀#2d964a다. 임의 CSS·색상·새 그림은 허용하지 않는다. 시안의 소개10자와 달리 채택 명세80자를 유지한다.

`artifacts/design-24/`의320/360/390/450/768/1440/1920 설정/공개 이미지,390/1440 배경 컨트롤을 원본과 비교했다. 이미지 선택/삭제·단일 적용·키보드·가로 넘침·아바타와 소개의 비중첩도 검사했다. 미확인/충돌·정리 안내는 기존 회색 안내/텍스트 버튼 패턴을 사용한다. 나머지 공개 헤더/카드/하단 및 메인 등의 차이는 #2의 후속 범위다. 이 단계가 전체 원본 정합 완료를 의미하지 않는다.

## 저장·보안·예산

- 기존 비공개 `animal-media` 버킷을 재사용한다. media_assets 용도를 animal/avatar/cover로 나누고 개체 ID는 animal에서만 필수다. 기존 개체 생존 검사 트리거를 animal에 한정하고 사진 연결에도 용도를 검사한다.
- 프로필 이미지 FK는 파일과 프로필의 복합 소유권을 강제한다. API는 용도/소유자/ready/만료/현재 연결을 잠금 아래 재검사한다. 연결/정리 경합에서 한쪽만 성공하며 참조 중인 파일은 물리 삭제 전 거절한다.
- 기존 파일 예산20MiB/계정을 공유한다. 예약450560 bytes(두 파일이 버킷 상한까지 올라올 가능성 포함), 계정 동시 예약2개·용도별 미연결 활성2개로 제한한다. 정리 대기 파일도 예산에 남는다.
- JPG/PNG/WebP15MB 이하만 브라우저에서 읽고, 방향 보정·중앙 자르기 후 avatar1:1/cover450:276 WebP 두 변형으로 인코딩한다. 서버가 실제 바이트/WebP 헤더/크기/치수/비율/SHA-256을 검사한다. 공통 상한 original≤225280 bytes/1280px, thumbnail≤81920 bytes/480px와 cover 비율 반올림 차이≤1px에 더해, 두 변형 합계는 프로필≤100KiB/배경≤200KiB다. 브라우저는 각각72+28KiB/150+50KiB로 인코딩하고 서버에서도 실제 합계를 검사한다.
- 표준 Supabase 서명 업로드 URL은2시간 유효하다. 기존의2시간5분 cleanup_after 임대와 create-only 토큰을 유지한다. 취소/교체는 delete_pending으로 기록하고 임대 종료와 실제 Storage 제거를 모두 확인한 뒤 예산을 반환한다. 테스트의 임대 시각 조정은 현재 실행의 폐기용 QA ID에만 적용한 만료 시뮬레이션이다.
- owner `my_design`은 기존 profile3필드/links/revision에 별도 options3필드와 정리 대기 개수를 추가한다. 공개 DTO에는 현재 이미지의 불투명 UUID와 허용 테마만 추가하며 경로·토큰·예산·영수증은 없다. 이미지 조회는 현재 연결/계정 활성/본인 또는 프로필 공개 조건을 따르고5분 서명을 사용한다. OG는 현재 배경→프로필→첫 개체 사진 순, 개체 상세는 해당 개체 사진을 사용한다.

`save_design`의 선택적5번째 options 인수를 생략하면 이전 이미지/테마를 보존한다. 생략한 요청의 해시도 이전 profile/items 형식 그대로여서 기존4인수 영수증 재전송을 유지한다. 새 옵션까지 포함한 저장은 프로필·SNS·파일·테마에 하나의 버전/24시간 영수증/롤백을 적용한다. 실제 변경이 있을 때만 한 번 revision을 올린다. 쓰기 중지 중 새 파일/테마/텍스트 변경은 막고 기존 파일 제거·SNS 숨김/삭제는 허용한다. 기존 SNS/프로필 API도 유지한다.

## 응답 유실과 복구

파일별 예약 UUID를 탭 메모리에 유지한다. 같은 예약 재시도는 기존 asset을 반환하고, 완료 응답이 유실돼도 같은 파일을 재검사/완료한다. 중복 경로의 create-only 충돌은 실제 서버 검사로 확인하고 덮어쓰지 않는다. 만료된 예약/ready 파일은 먼저 정리 대기에 넣은 뒤 새 예약을 만든다.

예약 응답 자체가 유실된 경우 취소 RPC는 같은 요청을 취소한다. 취소가 예약보다 먼저 잠금을 잡으면 취소 영수증을 남겨 뒤늦은 예약 생성을 막는다. 취소 목적으로 새 예약을 만들지 않는다. 저장 결과가 미확인이면 전체 명령과 업로드를 보존하고 입력/이동을 잠근다. 동일 영수증 재확인과 실제 조회 성공 후에만 잠금을 푼다. 실제로 연결된 파일은 취소하지 않는다. 버전 충돌의 최신 내용에는 텍스트/SNS/이미지/테마를 보여주고, 최신 설정 선택은 거절된 미연결 업로드만 정리한다. 서버의 이전 파일 정리 대기는 새 탭에서도 조회·재시도할 수 있다.

## 검증과 로컬 마이그레이션

추가 DB50개·단위2개·브라우저10개가 통과했다. 첫 DB 검사는 기존 개체 전용 트리거가 모든 media insert에 걸려 있음을 드러내 용도 조건을 명시했다. 브라우저 검사에서 적용 전 취소의 불필요한 서버 요청을 발견해 예약 시작 여부로 차단했다. 미확인 저장 검사는 두 번째 조회 종료를 기다리도록 보정했고 최종10개가 통과했다.

DB lint/보안 advisors 경고 이상 없음. CLI migration new의 빈 작업 파일을 제거하고 실제 `db pull --local`의 `20261029092351_profile_media.sql`과 용도별 합계 한도 보완 `20261029093930_profile_media_limits.sql`을 생성했다. 로컬 이력·shadow 비교를 확인하며 이전 migration/DB 데이터/볼륨은 초기화하지 않는다. 누적 `database/schema.sql`은 검토 snapshot이다. 전체 필수 구성은 build682개(하네스12·단위43·DB520·미디어10·Playwright97)이며 실제 최종 결과와 파일 해시는 `.local/harness-verification.json` 및 PR에 기록한다. 원격 OAuth·운영 배포·웹 콘솔 설정은 검증하지 않은 사용자 데스크톱 단계다.

최종 명세 대조에서 프로필100KiB/배경200KiB 합계 상한을 별도 보완했다. 위조 합계 거절2건과 실제 큰 PNG 재인코딩/저장1건을 추가했으며, 취소 후 정리 대기는 실제 재조회로 갱신한다. 생성 SQL의 끝 공백을 정리한 뒤 staged 전체를 검사하고 최종 필수 검증을 재실행한다.

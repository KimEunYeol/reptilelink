# 받은 알림·읽음 인계

이슈 #32. 선행 좋아요 #30 / PR #31은 build915개·최신18af545 리뷰 completed/no findings·명시적 squash 병합·이슈 종료·깨끗한 main79e5436과 검증 트리 일치로 완료했다. 이번 범위는 F-09 내부 알림·읽음과 원본 LIKE 관리 영역이다. 조회수 수집·실제 수치/그래프는 다음 독립 단계다.

## 데이터와 권한

`my_notifications`는 active 본인의 최근90일 받은 알림만5+1개 정밀 커서로 조회한다. `(created_at,id)` 역순이며 원문 시각의 microseconds를 그대로 커서로 돌려준다. 테이블·일반 역할의 직접 조회/변경 권한은 열지 않는다. 대상이나 수신자 ID를 인자로 받지 않으며 사용자 메타데이터 역할을 신뢰하지 않는다. 전체 최근 미읽음 수를 같은 snapshot에서 반환한다.

알림 본문·작성자 사진·프로필을 복제하지 않는다. 조회할 때 현재 댓글 visible·개체 공개/미삭제·대상 공개/active를 확인한다. 대상이 숨겨지면 원문/댓글 주소/작성자 이름/아바타를 제외하고 공통 ‘현재 확인할 수 없는 알림’만 표시한다. 공개·active 작성자의 이름/주소/프로필 이미지만 사용하며 나머지는 ‘회원’이다. Auth 사용자 UUID·이메일·내부 파일 경로는 없다. 좋아요 취소와 원래 관계의 삭제는 기존 FK로 알림을 함께 제거한다. 탈퇴 요청의 자기 댓글 원문 제거/외부 좋아요 제거와 최종 관계 정리를 유지한다.

`read_notifications`는 본인 알림1~5개 고유 ID 집합을 한 트랜잭션에서 처리한다. NULL/빈/중복/다차원/과대 입력, 타인/없는/90일 초과 ID가 섞이면 전체를 거절한다. `read_at=coalesce(read_at,now())`로 이미 읽은 시각을 유지하고 읽지 않음으로 되돌리는 명령은 없다. 쓰기 중지 중에도 읽음을 허용한다.

집합을 정렬해 동일 내용을 해시하고 UUID/작업/내용을24시간 영수증으로 확인한다. 다른 내용/작업은 REQUEST_CONFLICT, 만료는 REQUEST_EXPIRED다. 새 요청은 이미 읽음도 포함해 고정 시간당60회, 같은 영수증 재확인은 무료다. 읽음만으로 무제한 영수증을 생성하는 것을 방지하며 최대300개/시간의 표시 행을 처리할 수 있다. 실제 제한 기록은 기존47시간/시간별 배치 정리에 포함된다. 이 앱 제한은 공급업체의 요청 제한을 대신하지 않는다.

명령은 본인 계정 Share 잠금→영수증→전용 제한 기록→정렬된 본인 알림 행 순서다. 프로필/개체/다른 수신자 행은 잠그지 않는다. 기존 좋아요/저장과 같은 UUID, 알림 취소 FK와의 양방향 잠금, 탈퇴와 실제 동시 검사를 수행했다. 누락 ID/한도/충돌 때 영수증·제한·읽음은 함께 롤백된다.

## 화면과 복구

`/dashboard/activity`는 기존 관리 셸을 사용한다. LIKE 검색은 서버가 허용한 공개 DTO의 이름/‘회원’만 비교한다. 개인 이름을 별도로 가져오지 않는다. 원본처럼2명씩 좌우 이동하며 필요한 경우 제한된 다음 묶음을 명시적으로 불러온다. 초기 베타는 미삭제 프로필 최대10개·자기 좋아요 금지이므로 정상 전체 목록은9명 이하다. 소유자 프로필이 비공개여도 LIKE 관리 조회는 가능하다.

최신알림은5행/좌우 이전·다음과 명시적 새로고침이다. 읽지 않은 행의 텍스트 또는 ‘표시된 알림 읽음’을 눌러 처리하며 단순 조회로 읽음을 바꾸지 않는다. 현재 공개 댓글은 ‘댓글 보기’로 이동한다. 새로고침은 첫 페이지로 돌아간다. 자동 폴링·Realtime·이메일·푸시는 추가하지 않았다.

응답이나 저장 뒤 실제 조회가 불명확하면 동일 ID 집합/UUID를 보존하고 이동·검색·페이지 이동·다른 조작을 잠근다. 같은 요청과 실제 목록 조회가 확인된 뒤 해제한다. 단조 경과 시간/보수적인 벽시각 중 하나가24시간에 이르면 재전송을 중단하고 실제 최신 상태만 읽은 뒤 새 선택이 필요하다. 토큰 갱신은 요청을 유지하고 다른 사용자로 바뀌면 이전 요청을 재전송하지 않는다. 입력/명령을 브라우저 저장소에 별도 보관하지 않는다.

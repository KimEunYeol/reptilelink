# 모바일 프로필 사진 컨트롤 배치 (#70)

원본 `마이페이지-디자인수정-m.png`의 450px와 PC 화면은 프로필 미리보기 오른쪽에 등록·삭제 버튼과 설명을 둔다. 기존 CSS는 761px 이상에서만 이를 적용해 모바일에서는 버튼이 아래로 내려갔다. 보드 디자인 열(1950,1200,1200,4400)과 PC 공통 설명(0,8400,5000,1000)을 대조했다.

같은 grid 배치를 기본으로 적용하고 760px 이하의 간격,359px 이하의 미리보기/버튼 크기만 줄였다. 배경 이미지 컨트롤·공개 페이지·업로드/저장·DB/RPC는 바꾸지 않았다. 새 그림이나 패턴을 추가하지 않았다.

기존7폭 미디어 회귀에 실제 위치 검사를 추가했다. 기존 CSS의320px에서 버튼이 미리보기 아래에 있어 실패했고, 수정 후320/360/390/450/768/1440/1920px 모두 옆배치·가로넘침0이 확인됐다. 실제320·450·1440 캡처와 원본을 직접 비교했다. 관련 프로필/실제Storage/사진복구/공통관리26흐름도 통과했다. 캡처는 ignored `artifacts/profile-layout-70`,로그는 `.local/profile-70*`에 보존한다.

관련 검사의 첫 실행은25통과/1실패였다. 사진예약만 만료시키는 테스트에서 trace의 wall clock이1.135초 역행한 반면 monotonic time은 증가해 기존 명령 만료 보호가 동작했다. 운영 보호는 수정하지 않았다. 해당 테스트만 [Playwright setFixedTime](https://playwright.dev/docs/clock)으로 Date를 고정하고 실제 예약 만료를 DB 시각5분 전으로 설정·경과240초 이상을 검사했다. 단일 검사와 관련26흐름이 통과했으며 최초 실패 trace는 비공개 보존했다. 시간 역행 자체의 단위검사는 기존대로 유지한다.

고정 HEAD 전체검사와 최신diff 리뷰/PR/명시병합 결과는 실제 검증보고서·PR을 따른다. 이 문서는 운영 Google OAuth·정책/자산권리·공개 배포·원격복구 완료 증거가 아니다. 자료와 남은 작업은 [docs41](41-desktop-execution-checklist.md),[docs42](42-production-readiness.md),#62/#69를 따른다.

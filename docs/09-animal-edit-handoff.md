# 이슈 #3: 개체 수정 원본 비교·검증 기록

2026-10-28 사용자 정정에 따라 현재 WSL 개발환경에서 저장소 `design/`의 실제 PNG와 실행 화면을 직접 비교했다. 별도 데스크톱 앱에서의 비교를 대기 조건으로 두지 않는다. 외부 웹 콘솔 설정·운영 배포 검증은 여전히 별도다.

- 이슈: https://github.com/KimEunYeol/reptilelink/issues/3
- PR: https://github.com/KimEunYeol/reptilelink/pull/5
- 작업 브랜치: `codex/feat/3-animal-edit`, 작업 계약 `harness/tasks/3.json`
- 판정 범위: 일반 정보 편집창의 기존 원본 패턴·표시·저장/취소 동작. 전체 서비스나 원본의 모든 기능을 완료한 판정은 아니다.

## 실제 읽은 원본과 설명

- `design/렙타일링크_디자인.png`: 개체 관리 열 x5200~7200,y1250~6600. 추가/수정 팝업과 목록 ‘적용하기’가 별도이며, 팝업 하단에는 ‘저장’/‘취소’가 있다. 독립 수정 시안은 x6115~6465,y4280 부근에서 시작한다.
- 보드 PC 설명 x0~3700,y8380 부근: 메인 외에는 모바일과 같은 크기·레이아웃을 사용하고 상단/하단만 달리하며, 상세 팝업은 모바일 내용을 확인하고 그대로 진행하도록 설명한다.
- `design/마이페이지-개체관리.png`: PC에서도 중앙의 좁은 단일 콘텐츠 열.
- `design/마이페이지-개체관리-m.png`: 모바일 목록·하단 적용 버튼.
- `design/마이페이지-개체관리-m-1.png`: 약 340px 수정창, 큰 제목/닫기·구분선 헤더, 대표 사진, 부모 슬롯, 2열 성별, 구분선 입력 행. 보드에는 스크롤 아래 해칭일·설명·저장/취소도 있다.

보드의 설명 텍스트와 이미지에 실제 보이는 동작을 구분해서 읽었다. 추가 설명이 없는 부분에 임의의 저장 규칙을 전사하지 않았다. 사진·예시 연락처·화면 PNG를 제품 데이터나 배경 이미지로 복사하지 않았다.

## 원본과 실행 화면의 대조

| 항목 | 발견한 차이와 반영 | 결과/한계 |

| 팝업 배치·폭 | CSS reset 때문에 왼쪽 위에 붙던 창에 중앙 배치 적용, 넓은 화면에서도 약 340px 유지 | 7개 폭에서 중앙 배치 확인. 320/360px에서는 양옆 여백에 맞춰 축소 |
| 헤더 | 제목 크기·굵기와 100px 헤더/구분선/좌우 간격 보완 | 별도 장식 없이 원본 제목·닫기 패턴 재사용 |
| 사진 | 기존 대표 사진은 읽기 전용 유지 | 실제 업로드 이미지가 있는 상태에서 390/1440px 확인. 사진 없으면 해당 영역 생략 |

| 해칭일 | 길어져 줄바꿈되던 표시를 원본의 ‘해칭일’로 맞춤 | 접근성 이름은 ‘생일’. 네이티브 날짜 컨트롤의 날짜 순서·달력 아이콘은 브라우저/OS에 따름 |
| 분양 표시 | F-03에 필요한 상태 필드를 기존 입력 행 패턴으로 구성 | 새 카드나 별도 시각 방향을 만들지 않음 |
| 설명·저장/취소 | 원본의 구분선 설명 행과 초록 저장/회색 취소 버튼 쌍 유지 | 내부 스크롤로 하단 액션 접근, 취소 시 미저장·초점 복귀 확인 |
| 저장 동작 | 수정 중에는 DB/공개 데이터 유지, 팝업 저장은 즉시 해당 항목에 반영 | D-02/D-03과 일치. 목록 순서/공개 일괄 적용은 별도 범위 |

이는 #3 범위의 패턴 비교 통과다. 원본과 모든 픽셀이 같다는 판정이나 사용자의 PR 승인으로 기록하지 않는다.

## 실제 증거와 재현

로컬 캡처는 Git에서 제외하는 `artifacts/design-review-3/`에 있다.

- `comparison.png`: 원본·수정 전·수정 후 비교. 원본은 전체 편집 시안이며 실행은 이번 일반 필드만 포함하므로 전체 높이는 다르다.
- `responsive-overview.png`: 320/360/390/450/768/1440/1920px의 실행 화면을 열어 확인한 모음.
- `edit-<폭>.png`, `edit-bottom-<폭>.png`: 사진 없는 상태와 하단 조작.
- `photo-390.png`, `photo-1440.png`, `photo-bottom-*.png`: 실제 업로드 사진과 스크롤 후 저장/취소. 사진은 기존 브라우저 테스트가 생성한 검증 자료이며 승인된 브랜드 일러스트가 아니다.
- `edit-native.png`, `pc-notes.png`, `mobile-notes.png`: 바이트를 바꾸지 않은 보드의 비교용 크롭. 디자인 원본 97개는 변경하지 않았다.

7개 폭 모두 창과 문서의 가로 넘침, 라디오 크기, 하단 액션 접근, Tab/역방향 Tab, 취소 시 데이터 유지·개체 버튼 초점 복귀를 확인했다. 사진 있는 상태는 390/1440px에서 직접 검토했다. 최초 키보드 검사에서 네이티브 dialog의 Shift+Tab이 브라우저 툴바로 이동하는 것을 버튼 순환으로 잘못 가정해 실패했으며, 실제 문서 내 Tab/역방향 Tab 및 닫은 뒤 초점 복귀 검사로 수정해 통과했다.

```bash
# 구현/증거 재현은 main이 아니라 PR 작업 브랜치에서 한다.
git switch codex/feat/3-animal-edit
npm run local:start
npm run build
npm run dev:all
# 별도 터미널. 기존 서버가 있으면 재사용한다.
npm run verify
```

앱 `http://localhost:5173/dashboard/animals`, 빌드 앱·공개 HTML `http://localhost:8787`. `verify`는 QA 자료를 준비하며 기존 개발 DB를 초기화하지 않는다. 실제 자료를 QA 계정에 넣지 않는다. 검사 전용 암호·키·토큰은 캡처/문서에 노출하지 않는다.

전체 검사 구성: 하네스 12·단위 8·기존 DB 20·개체 수정 DB 55·미디어 8·Playwright 8, 총 111개와 build. 시각 일치는 이 숫자로 자동 판정하지 않고 위 원본 대조로 판단했다. 기존 500kB 번들 경고는 남는다.

## 남은 차이와 범위

- 원본의 ‘미표시’ 성별은 현재 F-03의 `unknown/male/female` 계약에 없다. 부모 개체·입양일·체중·성장 그래프·댓글·사진 교체/삭제도 이번 일반 수정 범위에 넣지 않았다. 비동작 컨트롤을 완성된 것처럼 표시하지 않는다.
- 날짜·종류 목록은 브라우저 기본 컨트롤로 원본의 사용자 정의 달력/목록과 내부 모양이 같지 않다. 원본의 정확한 폰트 파일도 제공되지 않아 시스템 대체 폰트를 사용한다.
- 기존 관리 화면의 사이드바/여러 열 카드, 로고/수제 Gecko, 헤더·푸터와 원본 중앙 단일 열/상단 탭의 차이는 계속 존재한다. 기존 목록 공개 토글의 즉시 저장도 원본의 목록 ‘적용하기’와 다르다. [이슈 #2](https://github.com/KimEunYeol/reptilelink/issues/2)에서 화면별로 추적한다.
- 이번에는 새 DB 변경·원격 DB/OAuth/Cloudflare 설정·배포를 수행하지 않았다. 최종 main 병합과 이슈 종료는 별도다.

작업 기록과 최종 파일 상태를 갱신한 뒤 전체 `verify`와 정상 pre-push 훅을 통과해 같은 PR에 반영한다. 별도 디자인 앱의 실행 여부를 완료 조건으로 사용하지 않는다.

## 구현한 사용자 흐름

관리 화면의 개체 카드/이름 선택 → ‘개체 수정’ 팝업 → 현재 값 확인 → 수정 → 저장 또는 취소. 수정 필드는 이름·종류·모프·성별·해칭일(생일)·설명·분양 상태다. 생일은 비워둘 수 있으며 실제 달력 날짜와 한국 날짜의 오늘까지 허용한다.

사진은 편집 팝업에서 기존 대표 사진만 읽기 전용으로 보여준다. 개체 공개 여부·소유자·사진 연결·성장 공개·순서는 일반 수정 명령으로 바꿀 수 없다. 사진/부모/입양일/체중/그래프와 삭제는 이번 구현 범위에 포함하지 않는다.

저장 중 중복 제출을 차단한다. 응답이 유실돼도 같은 입력의 재시도는 같은 요청 ID를 사용해 저장/버전 증가를 중복하지 않는다. 충돌은 입력을 보존하고 ‘최신 값 확인’ 후 ‘내 입력 유지’ 또는 ‘최신값으로 바꾸기’를 선택하게 한다. 선택 후 사용자가 다시 저장해야 반영된다. 오래된 입력을 자동 덮어쓰지 않는다.

## 데스크톱에서 실행

새 사본을 만들지 말고 같은 WSL 폴더와 작업 브랜치를 연다. 먼저 `git status --short --branch`로 브랜치/사용자 변경을 확인한다. 이미 서버가 있다면 재사용한다.

```bash
cd ~/projects/reptilelink
npm run local:start
npm run build
npm run dev:all
```

앱 `http://localhost:5173/dashboard/animals`, 빌드 앱·공개 HTML `http://localhost:8787`. 로컬 테스트 로그인은 개발 앱에서만 가능하다. 기존 테스트 브리더 또는 테스트 자료만 사용하고 실제 개체·연락처·민감한 자료는 입력하지 않는다. DB 초기화나 볼륨 삭제를 실행하지 않는다.

자동 기능 검증은 전용 QA 계정만 사용한다. 동일 흐름을 재현하려면 `npm run test:db` 다음 `npm run test:e2e -- tests/e2e/animal-edit.spec.ts`를 실행한다. QA 계정은 DB/미디어 검사에서 정리되므로 실제 자료를 보관하지 않는다. 테스트 암호·키는 채팅/문서에 복사하지 않는다.

## 검증·반영 절차

새 마이그레이션은 기존 개체에 NULL 생일을 추가했고 적용 전후의 기존 행 해시가 일치했다. 로컬 DB 보안 advisors에서 경고 이상 항목이 없었다. 원격 DB·OAuth·Cloudflare 리소스는 변경하지 않았다.

전체 검증 진입점은 `npm run verify`다. 기존 하네스 12·단위 8·기존 DB 20·수정 DB 55·미디어 8·브라우저 8개를 포함한다. 빌드의 기존 500kB 번들 경고는 남아 있다. 실행 결과는 `docs/05`와 무시되는 `.local/harness-verification.json`에 기록한다.

데스크톱 비교에서 차이가 있으면 같은 브랜치에서 보완한다. 완료 증거와 task 상태를 갱신한 뒤 다시 verify하고 push한다. 현재 pre-push 훅은 디자인 검토가 pending인 UI 변경을 거절한다. 이를 우회하지 않는다. 이후 main 대상 PR과 `Closes #3` 연결을 만들고 별도 병합 승인을 받은 뒤 main으로 복귀한다.

## 상태·시각·필터

상태 우선순위는 수동 종료 CLOSE → 상시 ALWAYS → 현재<시작 SOON → 시작≤현재<종료 OPEN → 종료≤현재 CLOSE다. private.schedule_status는 입력5개만 계산하는 immutable 함수로 테이블/특권 조회가 없다. anon/authenticated 실행을 명시 허용하지만 실제 읽기의 p_now는 서버 statement_timestamp다. 날짜마다 상태를 갱신하는 배치를 만들지 않는다.

브라우저는 서버 기준 시각에 performance.now의 경과를 더해 표시한다. Date.now를 잘못 설정해도 서버 상태가 유지되고 실제 시작/종료를 지나면 바뀐다. 공개 화면이 다시 보일 때 공개 RPC로 기준 시각을 갱신하며 실패 시 이전에 받은 값만 유지한다. 새로운 공개 요청은 RLS 조건을 다시 통과해야 한다. 이미 전달된 내용을 실시간으로 회수한다고 주장하지 않는다.

입력은 Asia/Seoul의 실제 IANA 규칙으로 UTC에 정규화한다. 고정+09만 가정하지 않는다. 존재하지 않는 벽시각은 거절하고 중복 시각은 PostgreSQL과 같은 나중 시각을 선택한다. 편집하지 않은 기존 초/밀리초는 원본 UTC 값을 유지한다. 실제 로컬 SQL과 단위 검사로1988 DST의 존재하지 않는02:30/중복02:30,1908의 자정 간격을 확인했다. 이는 운영 공급업체 시간대를 설정했다는 의미가 아니다.

기간 필터는 한국 시작일00시 이상/종료일 다음 날00시 미만과 겹치는 일반 일정 및 모든 상시 일정을 표시한다. 종료 시각과 필터 시작 경계가 같으면 겹치지 않는다. 자정이 없는 과거 날짜 경계는 PostgreSQL과 같은 전방 정규화를 적용한다. 필터 중에도 초안은 전체20개 집합을 유지하며 적용에 보이지 않는 항목을 누락하지 않는다. 순서 변경은 범위를 해제한 뒤 진행한다. 원본과 무관한 별도 필터 화면을 추가하지 않았다.

공식 근거는 [PostgreSQL Date/Time Functions](https://www.postgresql.org/docs/current/functions-datetime.html)다. 사용한 함수/연산은 현재 로컬 DB에서도 직접 확인했으며 DB/CLI/라이브러리를 업그레이드하지 않았다.

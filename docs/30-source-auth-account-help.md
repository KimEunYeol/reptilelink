# 원본 인증·기본정보·안내와 공개 복귀 (#38)

메인PR45/main88fdc6f 뒤의 독립 작업이다. 로그인/회원가입/기본정보/고객센터 PC·모바일8장과 전체 보드 인증·문의·약관(650,1000,1500,4900)/PC 공통(0,8400,5000,1000)을 직접 확인했다. 중앙 단일 폼·흰 테두리/회색 행·작은 도움말·스크롤 약관 창과 기존 원본 헤더/푸터를 사용했다. 실제 PC에서도 본문은 같은 좁은 폭이다.

## 표시와 기존 계약

로그인의 수제 Gecko/영문 장식·별도 카드를 제거했다. D01에 따라 자체ID/비밀번호/찾기/SMS 대신 기존 Google OAuth 버튼을 사용하며 새 Google 로고를 만들지 않았다. 운영 Google 연결 전 상태와 초대·승인을 안내한다. 개발용 로그인은 기존 loopback+DEV 조건에서만 보이고 운영 빌드에서 제외된다. 실제 원격 OAuth를 검증하지 않았다.

가입은 주소/이름/소개·필수 안내2개/전체 확인과 원본 약관 창을 사용한다. D06 최초 공개 후 주소 잠금은 유지하며 시안의 처음부터 변경 불가 설명을 적용하지 않는다. 기본정보는 주소/이름/본인 Auth 이메일(읽기 전용)/기존 소개를 같은 행 패턴으로 정비했다. 이메일을 프로필에 복제하거나 공개 DTO로 보내지 않는다. 기존 소개·공개 조작/용량/탈퇴의 기능 추가 행은 유지한다. 원본에 없는 비밀번호/전화·마케팅 동의·예시 운영자 자료는 추가하지 않았다.

기존 저장/revision/dirty·미확인/동일사용자 토큰 갱신·탈퇴 잠금을 유지했다. 온보딩 ‘변경 취소’는 실제 조회가 active/프로필 없음임을 확인해야 입력/확인을 비운다. 실패/빈 응답에서는 보존·잠금하고 다시 확인한다. 프로필이 이미 생겼으면 실제 값을 채택한다. 필수 확인 하나만 바꿔도 이탈/로그아웃/탈퇴 보호가 적용된다. 약관 창은 Escape/초점 복구·좁고 짧은 화면의 키보드 스크롤을 지원한다. SPA 뒤로가기에서는 약관을 닫고 기존 미저장 선택을 접근 가능하게 표시한다.

## 로그인 복귀와 로컬 Worker

공개 /u/slug 또는 /u/slug/animals/UUID만 허용한다. 외부 URL/이중슬래시/역슬래시/제어문자/encoded 경로/쿼리/해시/잘못된ID는 거절한다. 로그인 URL은 허용 경로를 한 번 인코딩하며 탭 저장소에는 path/createdAt만10분 보관한다. 만료/미래시각/형식 오류·저장소 차단은 정상 관리 진입으로 복귀한다. 토큰/회원정보/임시본문을 여기에 저장하지 않는다.

활성 기존 프로필은 해당 공개 root/detail로 한 번 복귀한다. 새 계정은 기존 승인/온보딩을 먼저 거치고 필수 확인과 프로필 생성 후 복귀한다. 중복 효과 실행에서 intent가 다시 저장되거나 두 번 소비되지 않도록 단일 결정을 사용했다. 기존 회원의 필수 문서 버전 연결/재동의는 독립#46으로 계속하며 모든 서버 쓰기 동의 검사는 유지했다.

[Supabase redirect 지침](https://supabase.com/docs/guides/auth/redirect-urls)과 설치된 auth-js의 detectSessionInUrl/implicit 기본 흐름을 확인했다. 기존 SDK 흐름을 유지하고 임의로 code exchange를 중복 호출하지 않았다. 취소/실패는 안전한 상태값으로 매핑하고 제공업체의 임의 error_description/토큰을 출력·별도 저장하지 않는다. SDK 초기화 전 오류 종류만 포착하며 복귀 URL을 정리한다.

wrangler.assets.run_worker_first에 인증/온보딩/관리 경로만 추가하고 해당 HTML에 no-store/no-referrer를 적용했다. 기존 /api·/u와 함께 실제 로컬 Worker에서 확인했다. CSS/JS/정적 자산은 직접 제공하며 모든 자산을 Worker로 보내지 않는다. 추가 동적 경로 요청은 운영 Worker 한도 점검 대상이다. 여기서 운영 빌드란 로컬8787의 Vite production build이며 Cloudflare 원격 배포가 아니다.

## 고객센터와 운영 자료

/help는 원본의 아이디/이메일/문의내용 폼을 제공한다. 실제 연락처가 없으면 준비 상태의 비활성 폼이며 접수/발송/제출 완료를 표시하지 않는다. 확인된 공개 VITE_SUPPORT_EMAIL이 있으면 사용자가 메일 앱에서 직접 발송할 초안만 연다. 주소/제목/본문·길이·URI를 검사/인코딩하며 서버 저장/SMTP/티켓/메일 API는 없다. 메일 앱 연결 시도는 실제 수신/접수 성공이 아니다. 현재는 연락처 미설정이며 외부 앱/발송/수신을 검증하지 않았다.

약관/개인정보 안내는 현재 개발 확인용 local-preview-v1 흐름이다. 원본의 회사/연락처/정책 본문을 운영 정보로 복사하지 않았다. 실제 운영 주체·법적 본문/연락처/권리는 사용자 desktop 자료가 필요하며 게시/버전 연결·기존 회원 재동의 준비는#46에서 마감한다. 이번 작업을 법적 문서/운영 가입 준비 완료로 주장하지 않는다. 정확한 폰트·Native 날짜/이탈 창 등 플랫폼 표현 차이는 유지한다.

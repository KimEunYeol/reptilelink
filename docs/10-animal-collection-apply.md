## 사용자 흐름과 저장 계약

목록의 순서·공개 여부를 변경 → 페이지 이동하며 초안 유지 → 적용하기 → 새로고침/재로그인/공개 페이지에서 확인한다. 화면은 한 번에 10개를 보여주고, 최대 20개 전체 ID/공개 상태를 순서대로 명령에 보낸다. 페이지 하나만 저장하는 경로는 없다.

초안은 탭 메모리에만 있다. 위/아래 버튼·키보드·동일 페이지의 드래그로 이동할 수 있고, 화살표로 페이지 경계도 넘는다. 적용 전에는 DB/공개 페이지가 바뀌지 않는다. 변경 취소는 저장하지 않고 되돌린다. 초안이 대기 중이면 개체 등록/편집·프로필 공개 전환·로그아웃은 먼저 적용/취소가 필요하다. 경로 이동/새로고침에는 유실 안내가 있으며 계속 수정 또는 명시적 버리고 이동을 선택한다.

적용 RPC는 프로필 잠금·활성/동의·전체 ID 집합·버전·입력/필드·영수증을 검증한다. 순서와 개체 공개만 변경하고 실제 변경 시 revision을 한 번 올린다. 같은 목록/빈 목록은 revision을 올리지 않는다. 응답 유실과 재조회 실패에서도 같은 요청 ID로 재시도해 중복 반영하지 않는다. 오류/충돌은 초안을 유지하고 최신 목록을 보여준 뒤 명시적 선택을 받는다. ID 집합이 달라졌으면 오래된 초안 유지를 허용하지 않는다. 사진/성장 공개/일반 필드/소유자/프로필 공개는 이 명령으로 변경할 수 없다.

공개 스위치는 미구현 반응 수 영역에 최소 조합했다. 가짜 댓글 수나 새로운 장식/브랜드는 만들지 않았다. 사진이 없으면 원본의 초록 면/그라데이션 패턴과 ‘사진 없음’을 사용하며 수제 Gecko를 새 목록의 기본 그림으로 재사용하지 않는다. 테스트에서 업로드한 그림은 이미지 처리 fixture이며 승인된 시안 자산이 아니다.

`artifacts/collection-6/list-{320,360,390,450,768,1440,1920}.png`를 열어 카드 폭·텍스트·조작·가로 넘침을 대조했다. `with-photo-390.png`, `with-photo-1440.png`와 `apply-bottom-390.png`는 실제 사진 상태·하단 페이지/적용 패턴 증거다. 생성 이미지/원본 PNG는 제품 화면 전체로 복사하지 않았다. 캡처·trace·키·실제 사용자 자료는 Git에서 제외한다.

공통 셸의 기존 사이드바/헤더/푸터/로고·수제 일러스트, 네이티브 날짜/목록과 정확한 폰트 차이는 #2에서 계속 추적한다. 이 작업은 목록 사용자 흐름의 패턴/동작 정비이며 전체 서비스를 원본과 픽셀 단위로 일치시킨 판정이 아니다. 사진/개체 삭제, 성장, 다른 관리 메뉴와 외부 콘솔 구성은 범위 밖이다.

## 로컬 DB 변경과 데이터 보존

테이블·공개 DTO 필드는 추가하지 않았다. 로컬에서만 새 함수로 반복 검증하고 보안 advisors의 경고 이상 없음 및 기존 행 해시 보존을 확인했다. CLI `db pull animal_collection_apply --local --schema api --yes`가 `20261028170427_animal_collection_apply.sql`을 생성하고 로컬 이력을 기록했다. CLI 출력의 remote history 표시는 --local 대상의 이력을 가리키며 원격 Supabase에 연결하지 않았다. 이전/초기 마이그레이션 재적용·개발 DB 초기화·볼륨 삭제는 하지 않았다.

writes_enabled=false에서도 같은 순서에서 숨기기는 허용하고 순서 변경/새 공개는 차단하는 기존 정책을 유지한다. 자세한 RPC 계약은 docs/02와 database/schema.sql의 검토용 스냅샷에 있다.

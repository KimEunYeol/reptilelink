## 구현에서 구체화한 사항

1. 사진이 있는 신규 개체는 먼저 비공개로 생성하고 업로드·검증·연결 후 최종 공개한다. Storage와 DB를 하나의 트랜잭션이라고 가장하지 않는다. 실패하면 저장된 비공개 개체를 사용자에게 알린다.
2. 단계 A의 변경 명령은 임의 테이블 UPDATE 권한 대신 소유권을 고정한 명시적 RPC를 사용한다. 내부 카운터·동의·사진 상태를 함께 갱신해야 하는 명령은 고정 search_path·역할별 EXECUTE·호출자 검사로 제한한 definer 함수다. 공개 조회는 invoker + RLS를 적용한다.
3. 사진 형식은 단계 A에서 WebP로 좁혔다. JPEG/PNG/WebP 입력을 브라우저에서 재인코딩하며, 서버는 크기·RIFF/codec 헤더·치수·허용 청크·해시를 확인한다. Chromium이 생성하는 4KiB 이하 ICC 색상 프로필은 허용하고 EXIF/XMP·애니메이션은 거절한다. 서버에서 전체 픽셀 디코딩·유료 변환을 수행하지 않는다.
4. 도메인에서 최대한의 오류 정보를 사용자에게 숨기며 SQL·토큰·내부 저장 경로를 공개 응답에 넣지 않는다.
5. 로고·일러스트는 이 저장소에서 작성한 벡터 표현이다. Figma 원본 자산의 사용 권한을 검증·반입한 상태가 아니다.
6. 로컬 동의 버전 `local-preview-v1`은 테스트 안내용이다. 실제 법적 문서를 완성한 것으로 간주하지 않는다.

## 이슈 #3: 개체 일반 필드 수정 — 로컬 검증·design 원본 비교 완료, PR #5

브랜치 `codex/feat/3-animal-edit`를 병합된 최신 main에서 생성했다. 이름·종류·모프·성별·해칭일(생일)·설명·분양 표시 상태의 수정/취소/저장을 구현했다. 원본 보드의 개체 수정 팝업을 참고하고 기존 대표 사진은 읽기 전용으로 제공한다. 사진 교체·삭제·개체 삭제·부모/입양일/체중/성장 기록·목록 공개/순서 일괄 적용은 이번 범위가 아니다.

CLI 생성 `20261028081719_animal_general_edit.sql`을 로컬에만 적용했다. 기존 개체 행의 생일 외 필드를 전후 해시로 비교해 보존을 확인했다. 새 수정 RPC는 활성 상태·소유권·동의·필드/타입/날짜·프로필 revision·요청 ID를 검증하고 사진/공개/소유자/정렬 변경을 거절한다. DB 보안 advisors의 경고 이상 항목 없음. 초기 마이그레이션이나 개발 DB를 초기화하지 않았다.

입력 검증 단위 8개, 기존 DB 20개와 개체 수정 DB 55개, 새 브라우저 흐름 5개를 확인했다. 수정 DB 검사는 동시 버전 충돌·같은 요청의 동시 재전송·같은 ID의 대상/본문 변경·권한·저장 유지·공개/비공개 격리를 포함한다. 브라우저는 390/1440px 취소/초점 복귀, 저장/재로그인/Worker 공개 HTML, 응답 유실 후 같은 요청 ID 재시도, 충돌 후 최신값 확인/입력 유지, 잘못된 입력의 저장 차단을 검증한다. 전체 회귀의 최종 결과는 task 기록과 `.local/harness-verification.json`을 참조한다.

사용자 정정에 따라 **현 개발환경에서 저장소 design/ 원본과 실제 실행 화면을 직접 대조**했다. 중앙에 놓이지 않던 팝업, 공통 입력 CSS 때문에 커진 라디오와 입력 행, 헤더 타이포·간격·해칭일 문구를 보완했다. 원본 종류 선택/직접입력 패턴은 datalist로 지원한다. [원본 비교 기록](09-animal-edit-handoff.md)에 기준 위치·대조표·실제 캡처·범위 차이를 기록했다. 기존 PR #5를 갱신하며 최종 병합·원격 OAuth·운영 배포·리소스 생성은 수행하지 않는다.

최종 입력 경계 검토에서 U+FEFF 공백에 대한 브라우저 trim과 DB 정규화의 차이를 확인했다. 기존 적용 마이그레이션은 유지하고 CLI 생성 `20261028083531_animal_edit_unicode_whitespace.sql`로 보완했다. 해당 공백만 있는 이름/종류 거절과 공백 제거 후 Unicode 길이 경계 검사를 추가했다.

로컬 Worker 미실행으로 첫 전체 검사가 중단되어 `dev:all`을 실행한 뒤 재검증했다. 최종 검증 범위는 빌드와 하네스 12·단위 8·기존 DB 20·수정 DB 55·미디어 8·브라우저 8개(총 111개)다. 원본 PNG와 실행 화면의 시각 대조는 자동 검사 수와 별개로 에이전트가 수행했다. 7개 폭에서 팝업 중앙 배치·가로 넘침·스크롤·키보드·취소 후 초점 복귀를 확인하고, 실제 사진이 있는 편집창도 390/1440px에서 확인했다. 전체 관리 화면·기존 수제 자산·목록 적용 방식 차이는 #2의 미해결 항목이다.

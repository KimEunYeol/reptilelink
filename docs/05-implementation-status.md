# 구현 진행 기록

착수일: 2026-10-27. 최종 로컬 검증: 2026-10-28. 작성한 명세·제안값을 기준으로 개발을 진행하라는 사용자 요청에 따라 D-01~D-08을 구현 기준으로 채택했다.

## 현재 구현 범위

| 항목 | 상태 |
|---|---|
| WSL 작업 디렉토리·Git·Node·로컬 Docker | 구성 |
| GitHub 비공개 저장소 | 생성, 초기 코드와 명세의 원격 저장소 |
| React·TypeScript·Vite·Tailwind UI | 메인, 인증, 프로필, 관리 목록, 등록 모달, 공개 페이지 |
| 실제 로컬 Auth와 승인 상태 | fixture 계정으로 동작·권한 검사 |
| 프로필 이름·주소·소개·공개 전환 | DB 저장·주소 잠금·버전 충돌 검사 |
| 개체 등록·공개 전환·상세 보기 | DB 저장, 개수 제한, 공개 조건 검사 |
| 사진 등록 | 브라우저 WebP 재인코딩·2개 변형, 예약·서버 검사·비공개 버킷·짧은 서명 URL |
| 실패·미사용 업로드 정리 | 취소 경로·로컬 만료 정리 명령 |
| 공개 HTML·공유 메타데이터 | 로컬 Worker에서 제목·설명·대표 이미지·404/no-store 처리 |
| 초기 마이그레이션 | CLI 생성·필수 초기 데이터 포함·빈 로컬 DB 재현 완료 |
| 원격 Google OAuth·초대 Hook 활성화 | 미연결·실제 공급업체 검증 전 |
| 무료 클라우드 배포·성능/한도 실측 | 아직 수행하지 않음 |

## 검증 증거

- 타입 검사와 production 빌드.
- 입력·오류·파일 구조 단위 검사 5개.
- 실제 로컬 Auth/DB/RLS/할당량 검사 20개.
- 업로드 API 인증·소유권·서명 토큰·바이트 검증·정리 검사 8개.
- Playwright 첫 흐름·빌드 로그인 제한·브라우저 WebP 호환 검사 3개.
- 브라우저에서 1440px 관리 화면, 390px 관리·공개 화면 촬영·검토. 모바일 공유 주소의 줄바꿈 문제를 수정했다.
- DB 보안 advisors의 경고 이상 항목 없음. 이는 애플리케이션 전체 보안 감사를 완료했다는 의미는 아니다.
- localhost 바인딩 확인. 원격 Supabase 프로젝트·Cloudflare 계정·유료 리소스는 생성하지 않았다.

빈 로컬 DB에서 마이그레이션·시드 재생성 후 Auth/DB 20개와 업로드 8개를 통과했고, WebP 색상 프로필·빌드 직접 진입을 보정한 최종 코드에서 빌드·Playwright 3개·DB 보안 진단을 통과했다. 테스트 trace·스크린샷·키·개발 DB·사진 본문은 저장소에 올리지 않는다.

## 구현에서 구체화한 사항

1. 사진이 있는 신규 개체는 먼저 비공개로 생성하고 업로드·검증·연결 후 최종 공개한다. Storage와 DB를 하나의 트랜잭션이라고 가장하지 않는다. 실패하면 저장된 비공개 개체를 사용자에게 알린다.
2. 단계 A의 변경 명령은 임의 테이블 UPDATE 권한 대신 소유권을 고정한 명시적 RPC를 사용한다. 내부 카운터·동의·사진 상태를 함께 갱신해야 하는 명령은 고정 search_path·역할별 EXECUTE·호출자 검사로 제한한 definer 함수다. 공개 조회는 invoker + RLS를 적용한다.
3. 사진 형식은 단계 A에서 WebP로 좁혔다. JPEG/PNG/WebP 입력을 브라우저에서 재인코딩하며, 서버는 크기·RIFF/codec 헤더·치수·허용 청크·해시를 확인한다. Chromium이 생성하는 4KiB 이하 ICC 색상 프로필은 허용하고 EXIF/XMP·애니메이션은 거절한다. 서버에서 전체 픽셀 디코딩·유료 변환을 수행하지 않는다.
4. 도메인에서 최대한의 오류 정보를 사용자에게 숨기며 SQL·토큰·내부 저장 경로를 공개 응답에 넣지 않는다.
5. 로고·일러스트는 이 저장소에서 작성한 벡터 표현이다. Figma 원본 자산의 사용 권한을 검증·반입한 상태가 아니다.
6. 로컬 동의 버전 `local-preview-v1`은 테스트 안내용이다. 실제 법적 문서를 완성한 것으로 간주하지 않는다.

## 아직 구현하지 않은 명세

- 프로필 아바타·커버 업로드, SNS·테마 편집 확장.
- 개체의 일반 필드 수정·삭제 UI, 순서 일괄 적용, 생일 필드.
- 사진 교체·삭제 UI와 더 상세한 실패 복구 경험.
- 성장 기록·비공개 메모 편집, 외부 링크, 일정.
- 댓글·좋아요·신고·내부 알림·통계.
- 계정 탈퇴·인증 세션 해지·백업 내 삭제·실제 복구 실험.
- 실제 OAuth, 가입 전 허용 목록 Hook 연결, 운영 정책 문서.
- 모든 명세 화면 크기의 검증과 전체 접근성 점검. 초기 브라우저 검증은 390/1440px 중심이다.
- 운영 무료 플랜 확인·배포·실제 공유 앱의 OG 캐시 확인·Worker CPU 측정.

## 2026-10-28 개발 하네스·GitHub·디자인 기준 점검

파일럿: [이슈 #1](https://github.com/KimEunYeol/reptilelink/issues/1), `codex/chore/1-agentic-harness`. 최신 `origin/main`의 `d044045`에서 분기했고 기존 IDE 인계 커밋을 cherry-pick해 보존했다. 기존 `codex/wsl-vscode-setup` 브랜치와 사용자 PNG 원본을 변경하거나 삭제하지 않았다.

- 기존에는 이슈/PR 템플릿·분류 라벨·기능별 main 분기·디자인 검토 계약이 없었다. AGENTS/시작 안내/첫 작업 프롬프트/IDE 작업에 [개발 하네스](07-agentic-workflow.md)를 연결했다.
- 원본 PNG 97개(17,542,550 bytes)를 Git 추적 대상으로 추가하고 경로·치수·SHA-256 인벤토리를 만들었다. 전체 보드 설명과 PC/모바일 화면 참조·새 창작 금지·기존 패턴 재사용·시안/기능 충돌 기록 기준은 [디자인 계약](08-design-contract.md)에 있다. 자동 검사는 의미/시각 일치 판정을 대신하지 않는다.
- `task:start`, `harness:install/check`, `design:check/inventory`, `verify`와 pre-commit/pre-push를 구성했다. main/다른 ref/강제 갱신, 디자인 기록 누락, 미검증 파일 상태를 거절한다. 소스·도구 변경에는 문서 전용 검사로 우회할 수 없다. task:start는 사용자 변경을 자동 stash/reset하지 않는다.
- GitHub 16개 관리 라벨, 기능/버그 이슈 폼, PR 템플릿, CODEOWNERS를 추가했다. Issues·squash 전용 병합·PR 제목/본문 기본값·병합 브랜치 자동 정리·Update branch 활성과 auto-merge 비활성을 실제 API로 적용·재조회했다. Actions는 저장소 권한 자체를 비활성으로 변경하고 재확인했다. 저장소 비공개와 main 기본 브랜치를 유지했다.
- Rulesets와 main branch protection 조회는 현재 비공개 Free 플랜에서 모두 403으로 거절됐다. 유료 전환·공개 전환 없이 로컬 훅과 PR 검토를 사용한다. 로컬 훅은 우회 가능하며 서버 보호를 활성화한 상태가 아니다.

실행 결과: production build 성공(기존 번들 500kB 초과 경고 유지), 단위 5개, 실제 로컬 Auth/DB/RLS/한도 20개, 업로드 API 8개, Playwright 3개 통과. 하네스 회귀 12개는 잘못된 브랜치·이슈/디자인 기록·stale/불완전 테스트 증거·비정상 push·디자인 변경 감지 및 실제 임시 Git 저장소의 main 분기/사용자 변경 보존/기존 훅 보존을 포함한다. 샌드박스 내 Node 자식 프로세스·Docker 접근은 EPERM/권한 오류여서 허용된 로컬 실행 권한으로 재검증했다. DB 초기화·운영 OAuth·원격 배포는 수행하지 않았다.

# 렙타일링크 기능 명세 v0.1

기준일: 2026-10-27 · 상태: 검토 가능한 설계 초안 · 개발 환경: 로컬 WSL · 배포 예산: 추가 지출 0원

## 1. 목적과 역할

브리더가 개체 정보를 등록하고 성장 기록·일정·외부 링크를 하나의 공개 주소로 제공한다. 방문자는 공개된 정보만 보고, 로그인한 회원은 허용된 반응 기능을 사용한다.

| 역할 | 할 수 있는 일 |
|---|---|
| 방문자 | 공개 프로필·개체·일정·링크·공개 성장 기록 읽기 |
| 로그인 회원 | 자신의 승인 상태 확인, 공개 페이지에 댓글·좋아요 사용(확장 단계) |
| 활성 브리더 | 자신의 페이지 생성·공개 설정, 자신의 콘텐츠 관리 |
| 운영자 | WSL의 관리 작업 또는 제공업체 관리 화면으로 승인·중지·사용량 점검·복구 |

초기에는 운영자용 웹 화면을 만들지 않는다. 운영 권한은 프런트엔드에서 전달하는 역할 값이나 수정 가능한 사용자 메타데이터로 판정하지 않는다.

## 2. 범위와 출시 단계

| 단계 | 범위 | 완료 결과 |
|---|---|---|
| A: 첫 배포 | 인증, 계정 승인, 프로필, 개체·사진, 공개 페이지, 무료 배포 검증 | 브리더가 개체를 등록하고 URL로 공유할 수 있다 |
| B: 관리 기능 | 성장 기록, 외부 링크, 일정, 디자인 설정, 탈퇴·정리 절차 | 핵심 관리 시안을 실제 데이터로 사용할 수 있다 |
| C: 방문자 기능 | 댓글·좋아요, 내부 알림, 방문 통계, 신고·운영 대응 | 시안의 반응·통계 흐름을 무료 예산 안에서 제공한다 |

최종 개발 범위는 A~C다. 단계를 나눈 것은 구현·검증 순서이며 뒤 단계의 기능을 완료했다고 간주하지 않는다.

초기 제외 범위: 결제·거래 중개, 분양 대금 처리, 유료 SMS/본인인증, 동영상, 원본 대용량 사진 보관, 실시간 채팅, 외부 푸시·메일 알림, 네이티브 앱스토어 배포, 제품 내 생성형 AI.

## 3. 기본 동작 제안

| ID | 기본안 | 이유·영향 |
|---|---|---|
| D-01 | Google 소셜로그인으로 첫 배포 | 자체 인증 메일 발송 경로 없이 시작. 시안의 아이디·비밀번호·아이디 찾기는 첫 배포에서 대체한다 |
| D-02 | 영역별 ‘적용하기’로 저장 | 토글·순서·입력값은 적용 전 브라우저 상태. 별도의 서버 임시저장 버전은 만들지 않는다 |
| D-03 | 저장된 변경은 공개 중인 페이지에 바로 반영 | 별도 게시 승인 단계 없음. 공개 페이지는 처음에는 비공개 |
| D-04 | 성장 수치 공개는 개체별 별도 동의, 초기 꺼짐 | 개체 카드 공개와 기록 공개를 구분. 관리 메모는 항상 비공개 |
| D-05 | 댓글·좋아요는 활성 회원만 | 익명 쓰기를 허용하지 않아 남용·사용량을 줄인다 |
| D-06 | 최초 공개 이후 고유 주소 변경 금지 | 기존 공유 링크·중복 주소·리다이렉트 복잡도를 줄인다 |
| D-07 | 초기 미삭제 브리더 프로필 최대 10개, 초대·승인제와 계정별 예산 적용 | 공개 베타 규모를 제한하고 무료 자원 사용량을 먼저 측정한다 |
| D-08 | 일정 상태는 날짜·수동 종료에서 계산 | 예약 상태 갱신을 위한 잦은 배치 실행을 줄인다 |

2026-10-27 사용자가 작성한 명세와 제안값을 기준으로 개발을 시작하도록 승인했다. D-01~D-08을 현재 개발 기준으로 채택한다. 실제 외부 OAuth·운영 배포 검증과 로컬 fixture 검증을 구분한다. 변경 시 명세와 데이터 구조를 함께 갱신한다.

| 경로 | 시안·용도 | 단계 |

| `/onboarding` | 약관 동의·고유 주소·프로필 생성·승인 상태 | A |

## 5. 공통 저장·공개 규칙

1. 입력을 바꿔도 ‘적용하기’ 이전에는 공개 데이터가 바뀌지 않는다. 저장하지 않고 이동할 때 변경 유실 안내를 표시한다.
2. 개체·링크·일정 팝업의 ‘저장’은 해당 항목을 즉시 저장한다. 목록의 정렬·노출 토글은 목록의 ‘적용하기’로 함께 저장한다. 팝업 저장과 목록 변경이 동시에 대기하면 먼저 목록을 적용하거나 취소하도록 안내한다.
3. 한 번의 적용은 트랜잭션이다. 일부만 저장된 상태로 성공 메시지를 표시하지 않는다.
4. 변경 대상의 버전을 보내고 최신 버전과 다르면 `VERSION_CONFLICT`로 거절한다. 다시 불러오기와 입력 내용 복사 선택지를 제공한다.
5. 페이지는 첫 생성 시 비공개다. 활성 계정·필수 동의·프로필 검증을 통과해야 공개 가능하다. 콘텐츠가 없는 공개 페이지는 빈 상태를 표시할 수 있다.
6. 공개 조건은 계정 활성 + 프로필 공개 + 해당 항목 공개다. 성장 기록·사진·댓글에는 상위 항목의 공개 조건도 적용한다.
7. 비공개·없는 페이지·중지 계정은 외부에 동일한 404를 반환한다. 인증 실패를 공개 데이터로 대체하지 않는다.
8. 비공개 전환 후 새 조회·파일 접근 요청은 거절한다. 이미 전달한 이미지나 기존 서명 URL은 즉시 회수할 수 없으며, 이미지 URL 유효기간은 최대 5분으로 제한한다.
9. 삭제는 공개 노출부터 차단하고 파일·연관 데이터를 정리한다. 정리가 실패하면 상태를 남겨 재시도하고 실제 제거 전에는 용량을 반환하지 않는다.
10. 브라우저 저장소에 토큰·개인정보가 포함된 임시 입력을 별도로 장기 보관하지 않는다. 초기 초안은 탭 메모리에만 둔다.

## 6. 기능별 명세와 수용 기준

### F-01. 로그인·승인·계정

- 초기 베타는 초대된 Google 계정만 가입할 수 있게 한다. Auth의 Before User Created 훅에서 비공개 허용 목록을 확인한 뒤 최초 `pending` 계정을 생성한다. 활성 승인 전에는 브리더 페이지 생성·업로드·댓글·좋아요를 허용하지 않는다.
- 승인 처리는 운영자만 수행한다. 신규 프로필은 동시 요청을 포함해 활성 브리더 한도 안에서만 생성된다.
- 승인 후 필수 약관 동의와 고유 주소 설정을 마쳐 이용한다. OAuth 주소의 허용 목록은 로컬·배포 환경별로 분리한다.
- 이메일·제공업체 계정 정보는 인증 서비스에서 관리하며 공개 프로필에 복제하지 않는다.
- 개인정보 화면에는 본인 계정에 필요한 정보만 제공한다. 로그아웃 후 관리 화면을 다시 열면 인증을 요구한다.
- 탈퇴 요청 즉시 계정을 `deleting`으로 바꾸고 공개 페이지·신규 쓰기를 막는다. 세션 해지와 파일 정리 후 인증 계정을 삭제한다. 정리 완료 전 다시 활성화하지 않는다.

수용 기준: 초대되지 않은 신규 가입 거절. A/B 두 계정의 토큰을 교체해도 상대 데이터 변경 불가. `pending` 회원의 API 직접 호출 거절. 신규 동의 버전·시각 기록. OAuth 취소·만료 오류에서 재시도 가능. 탈퇴 후 기존 토큰으로 콘텐츠 읽기·쓰기 불가.

### F-02. 프로필·디자인·SNS

- 고유 주소: 소문자 영문·숫자·하이픈, 3~30자, 시작·끝은 영문 또는 숫자. 예약어와 중복 주소 거절.
- 표시 이름 1~40자, 한 줄 소개 최대 80자, 소개 본문 최대 300자. 공백만 있는 이름 거절.
- 프로필·배경 이미지, 허용된 테마 색상, SNS 종류별 URL·노출 여부 편집.
- 테마는 사전 정의된 색상 토큰만 선택. 임의 CSS·HTML·스크립트 입력 없음.
- 초기 SNS 종류: band, instagram, facebook, youtube, kakao, naver_blog. 같은 종류는 한 프로필에 한 개. 원본 순서를 고정하며 별도 정렬 UI는 없다. 주소/노출은 전체6종을 적용하기로 저장하고 비공개+빈 주소는 삭제한다. 공개할 SNS에는 유효한 HTTPS 주소가 필수다. 쓰기 중지 중에도 기존주소 숨김/삭제는 허용한다.
- 새 이미지를 적용하기 전에는 기존 이미지를 유지한다. 취소한 업로드는 정리 대기 상태로 보낸다.
- 페이지 소개/이름/설명과 SNS6종은 원본의 단일 폼·하단 적용하기로 한 번에 저장한다. 이름/한 줄 소개는 줄바꿈/제어문자를 거절하며 Unicode 코드포인트로 길이를 검사하고 앞뒤 ECMAScript 공백을 정리한다. 설명의 내부 줄바꿈은 보존한다. 변경이 있으면 전체 프로필/SNS에 한 revision·24시간 영수증을 적용한다.
- 프로필 텍스트가 그대로일 때 쓰기 중지 중 SNS 숨김/삭제는 가능하다. 프로필 텍스트 변경과 새 SNS 쓰기는 거절하고 일부만 적용하지 않는다. 공개 소개·이름·설명에는 실제 저장값만 쓰며 빈 소개/설명을 임의 사용자 문구로 대체하지 않는다.

수용 기준: 중복 주소의 동시 생성 중 하나만 성공. 미적용 변경은 외부에 보이지 않음. 공개 프로필 저장 후 새 요청에서 갱신됨. 다른 계정의 이미지 ID를 연결하면 거절.

### F-03. 개체·사진

- 이름 필수 1~40자, 종류 필수 1~80자, 모프 최대 120자, 성별 `unknown/male/female`, 생일 선택, 설명 최대 500자.
- 분양 표시 상태는 `not_listed/available/reserved/rehomed`. 화면 문구로 매핑하며 거래·결제 기능으로 사용하지 않는다.
- 공개 여부, 성장 수치 공개 여부, 표시 순서를 각각 저장한다.
- 개체별 사진 최대 3장, 대표 사진 한 장. 사진 없이도 기본 일러스트로 저장 가능.
- 비공개 관리 메모는 공개 설명과 별도 데이터로 저장한다.
- 목록은 한 번에 10개, 최대 요청 크기 20개. 순서는 `sort_order, id`로 안정적으로 정한다.
- 정렬은 드래그와 위·아래 버튼을 함께 제공한다. 전체 항목 ID 집합을 검증해 순서 교체를 한 번에 적용한다.
- 개체 삭제는 저장하지 않은 편집/목록 변경을 먼저 해결한 뒤 개체 이름과 복구 불가 안내를 보고 명시적으로 확인한다. 즉시 관리·공개 목록과 새 사진 접근을 차단하고 정리 대기로 남긴다. 사진·예약 파일이 모두 제거된 뒤 개체/비공개 메모를 최종 삭제한다. 그 전에는 개체 20개 한도와 파일 예산에 포함하며 남은 개체 정렬은 허용한다. 정리 대기는 본인만 확인·재시도한다.

수용 기준: 등록→새로고침→재로그인 후 동일 데이터. 비공개 개체의 ID 직접 조회·사진 요청 거절. 21번째 개체·4번째 사진을 서버에서도 거절. 정렬 도중 실패하면 이전 순서 유지.

### F-04. 성장 기록

- 날짜와 무게(g)를 기록한다. 무게는 양수, 소수 둘째 자리까지. 같은 개체·같은 날짜는 한 건이며 수정으로 정정한다.
- 미래 날짜는 허용하지 않는다. 날짜는 브리더 시간대 기준이며 초기 시간대는 Asia/Seoul이다.
- 일별 기록을 주·월·년 범위로 조회한다. 그래프는 해당 기간의 기록된 날짜를 시간순으로 표시하며 빈 날짜의 수치를 만들지 않는다.
- 주간/월간/년간은 서버의 한국 날짜 기준 오늘을 포함한 최근 7/30/365일이다. 그래프는 최대 120포인트로 실제 날짜를 유지해 표본화하고 첫/마지막 관측을 포함한다. 빈 날짜의 수치를 보간해 저장하거나 가짜 포인트를 만들지 않는다. 상세 목록은 최신 날짜부터 20건씩 커서로 조회한다.
- 개체 공개와 별도로 `show_growth=false`가 기본. 기록별 비공개 메모는 어떠한 공개 응답에도 포함하지 않는다.

수용 기준: 날짜 중복·음수·과도한 자릿수 거절. 입력 순서가 달라도 그래프는 날짜순. 공개 성장 설정을 끄면 기록 API 직접 조회도 거절.

### F-05. 외부 링크·SNS URL

- 사용자 지정 링크는 제목 1~40자, URL 최대 2,048자, 색상 토큰, 노출 여부, 순서를 가진다. 최대 10개.
- URL은 HTTPS만 허용하고 자격증명 포함 URL, `javascript:`, `data:`, 제어문자를 거절한다.
- 서버가 입력된 URL을 가져와 썸네일·메타데이터를 수집하지 않는다. 내부 IP 접근·외부 fetch 증가를 방지한다.
- 새 창 링크는 `rel="noopener noreferrer"`를 사용한다. 제목·설명은 HTML로 해석하지 않는다.
- 입력은 WHATWG URL로 ASCII/IDN·기본 포트·경로를 정규화한 뒤 2,048자를 검사한다. 서버도 ASCII HTTPS·호스트/IP·포트·percent escape·자격증명/제어문자/역슬래시를 독립 검증하며 URL을 fetch하지 않는다. 색상은 원본의 black/gray/blue/mint/green/light-pink/pink/red/purple/yellow/orange 11개 토큰만 허용한다.
- 팝업은 새 항목을 비공개로 즉시 저장한다. 목록 순서·노출·삭제는 전체 본인 ID 집합을 적용할 때 원자적으로 반영한다. 삭제는 적용 전 취소 가능하며, 쓰기 중지 중에도 상대 순서를 유지한 숨김/삭제/정렬 간격 압축은 허용한다.

수용 기준: 저장된 공개 링크 순서와 노출이 정확함. 비공개 링크는 공개 응답에서 누락. 잘못된 URL은 입력창과 API 양쪽에서 거절.

### F-06. 일정

- 제목 1~80자, 설명 최대 300자, 시작·종료 시각, 상시 여부, 수동 종료, 노출 여부, 순서.
- 일반 일정은 시작·종료 필수, 종료가 시작보다 뒤여야 한다. 상시 일정은 시작·종료를 비워 둔다.
- 공개 상태 계산 우선순위: 수동 종료=`CLOSE`; 상시=`ALWAYS`; 현재<시작=`SOON`; 시작≤현재<종료=`OPEN`; 종료≤현재=`CLOSE`.
- UTC로 저장하고 Asia/Seoul로 표시한다. 클라이언트 시계만 신뢰하지 않으며 API의 기준 시각으로 표시를 보정한다.
- 반복 일정은 초기 제외. 목록 최대 20개, 날짜 범위 필터 지원.
- 기간 필터는 한국 달력의 시작일/종료일을 포함하며 일반 일정의 반열린 기간과 겹치는 항목, 상시 일정을 표시한다. 필터 중에는 순서 변경을 잠그고, 보이지 않는 일정도 전체 목록 적용 집합에 보존한다.
- 팝업의 신규 일정은 서버 ID/비공개로 즉시 저장한다. 순서·노출·삭제는 전체 본인 ID/삭제 집합으로 적용한다. 쓰기 중지 중 상대 순서를 유지한 숨김/삭제/간격 압축과 기존 내용 그대로 수동 종료는 허용하며, 새 내용/새 공개/실제 재정렬/종료 취소는 차단한다.
- 입력은 한국 일시를 실제 Asia/Seoul 규칙으로 UTC 정규화한다. 존재하지 않는 벽시각은 거절하고 중복 시각은 PostgreSQL과 같은 나중 시각을 선택한다. 편집하지 않은 기존 초/밀리초는 보존한다. 화면 상태는 서버 기준 시각+단조 시계 경과로 보정하며 브라우저 Date.now를 신뢰하지 않는다.

수용 기준: 시작·종료 경계 시각의 상태가 정확함. 비공개 일정이 노출되지 않음. 잘못된 기간·상시와 날짜의 혼합 입력 거절.

### F-07. 공개 페이지·공유

- 프로필 → 공개 일정 → 공개 개체 카드 → 공개 외부 링크 → 공개 SNS 순서로 구성한다.
- 카드에서 상세 팝업 열기, URL 직접 진입에서는 독립 상세 화면 표시. 뒤로가기로 목록 상태 복구.
- URL 복사는 HTTPS 공개 주소를 사용한다. 비공개 상태의 공유 버튼은 먼저 공개 설정을 안내한다.
- 페이지별 제목·설명·대표 이미지 메타데이터를 초기 HTML에 제공해 공유 미리보기를 지원한다. 임의의 외부 이미지를 서버가 가져오지 않는다.
- 공개 상세에 등록되지 않은 개체 ID를 다른 브리더 경로에 넣으면 404. 외부 SNS가 이미 수집한 공유 미리보기는 비공개 전환만으로 즉시 회수할 수 없음을 안내한다.
- 공개 응답·메타데이터에는 이메일·계정 승인 상태·관리 메모·파일 경로·저장 사용량을 넣지 않는다.

수용 기준: 비로그인 브라우저에서 공개 페이지와 링크 동작. 링크를 붙여 넣었을 때 올바른 초기 HTML 메타데이터. 비공개 전환 이후 새 요청의 내용과 미리보기 노출 차단.

### F-08. 댓글·좋아요·운영 대응

- 온보딩을 마친 활성 회원이 공개 개체에 일반 텍스트 댓글 1~500자를 작성한다. 첨부·HTML·답글·멘션 알림은 초기 제외.
- 작성자는 자신의 댓글 삭제, 페이지 소유자는 자기 개체 댓글 숨김, 운영자는 신고 확인 후 숨김 가능. 상대 댓글 내용 수정은 불가.
- 댓글은 개체별 최대 200개, 사용자별 분당 3회·일 30회 작성. 제한 값은 서버에서 강제한다.
- 프로필 좋아요는 회원·프로필당 한 개. 재요청은 토글하지 않고 원하는 최종 상태로 처리한다. 자기 프로필 좋아요는 불가. 추가·취소를 합해 계정당 시간 60회로 제한한다.
- 신고는 개체·댓글 ID와 사유 코드·짧은 설명으로 접수하며 운영자만 조회한다. 운영 절차 없이 댓글을 공개 출시하지 않는다.

수용 기준: 중복 좋아요가 증가하지 않음. 타인 댓글 삭제·수정 거절. 숨겨진 댓글은 ID 조회도 거절. 서버 제한을 직접 API로 우회할 수 없음. 신고 접수자가 다른 사람의 신고를 읽을 수 없음.

### F-09. 알림·통계

- 알림은 자기 개체의 새 댓글·프로필의 새 좋아요를 사이트 내부 목록으로 표시한다. 읽음 처리와 최근 90일 조회. 이메일·푸시·실시간 연결은 없음.
- 방문 통계는 페이지 조회수로 명명한다. 사람 수·고유 방문자 수로 표현하지 않는다.
- 한 브라우저 탭 세션이 같은 프로필을 같은 한국 날짜에 여러 번 열면 한 번 집계하는 기본안. 식별자는 무작위 세션 값이며 원문은 서버에 보관하지 않는다.
- 서버는 날짜별 해시를 사용한 중복 방지 영수증을 최대 48시간 보관하고 일별 수치만 남긴다. IP·사용자 에이전트·이동 경로 원문은 통계 DB에 저장하지 않는다.
- 통계 수집 실패로 공개 페이지가 실패하지 않는다. 봇·세션 초기화에 따라 중복될 수 있는 참고 지표로 표시한다.

수용 기준: 동일 이벤트 재전송 시 증가 없음. 날짜 경계 Asia/Seoul 적용. 다른 브리더 통계 조회 거절. 만료 영수증 정리 후에도 일별 누적값 유지.

### F-10. 사용량·업로드 제한

- 계정별 개체 20개, 사진 3장/개체, 링크 10개, 일정 20개, 성장 기록 3,000건/계정.
- 파일 저장 예산은 계정당 20MiB. 임시 업로드·교체 전 파일·정리 대기 파일도 포함한다.
- 개체 사진은 상세용 220KiB + 썸네일 80KiB 이내. 프로필 100KiB, 배경 200KiB 이내. 모든 변형 파일 합계를 계산한다.
- 브라우저에서 방향 보정·크기 조정·재인코딩해 메타데이터 제거. 저장 형식은 JPEG/WebP만. SVG·GIF·동영상·원본 파일은 저장하지 않는다.
- 서버·DB·Storage에서도 크기·소유권·형식·개수·용량을 검증한다. 클라이언트의 용량 보고만 믿지 않는다.
- 제한 도달 시 현재 데이터 조회·백업·삭제는 가능한 범위에서 유지하고 새 쓰기를 제한한다. 제공업체가 전체 서비스를 중지할 수 있다는 안내도 둔다.

수용 기준: 동시 업로드로 계정·프로젝트 예산을 넘지 않음. 거짓 MIME·변조된 파일·다른 소유자의 저장 경로 거절. 실패한 업로드가 영구적으로 용량을 잠그지 않음. 정리가 끝나지 않은 바이트를 먼저 반환하지 않음.

## 7. 화면 품질과 오류 계약

- 기준 시안은 모바일 폭 450px·PC 폭 1920px. 검증 화면은 360·390·450·768·1440·1920px이며 320px에서도 주요 기능 조작을 확인한다.
- 관리 탭의 가로 이동은 의도된 탐색 영역으로 한정하고, 페이지 전체에 불필요한 가로 스크롤을 만들지 않는다.
- 공통 상태: 로딩, 빈 목록, 저장 중, 업로드 실패, 네트워크 끊김, 권한 없음, 미공개, 사용량 제한, 동시 편집 충돌.
- 키보드로 탭·버튼·정렬·모달을 조작 가능. 모달 초점 이동·복귀, 입력 라벨, 오류 연결, 대비를 확인한다.
- 원본 폰트·로고·일러스트의 사용 가능 여부를 확인한다. 확인되지 않은 시안 자산은 임의로 외부 배포하지 않는다.
- API 응답은 성공 데이터와 오류를 구분한다. 오류는 `code`, 사용자용 `message`, 필요한 경우 `field_errors`, `retry_after`를 가진다. SQL·토큰·내부 경로는 반환하지 않는다.

## 8. 구현 전 검토할 결정

1. Google 로그인 대체안과 초기 승인제 10명.
2. 영역별 적용·즉시 공개 반영과 최초 공개 후 주소 고정.
3. 성장 기록 공개 기본값, 댓글·좋아요의 로그인 조건.
4. 개체·사진·저장량 등 초기 제한 값.

### F-02 파일·테마 실제 저장 보완 (#24)

프로필/배경·허용3색도 소개/SNS의 단일 적용에 포함한다. 선택/취소는 업로드 전 서버 쓰기 없이 탭 메모리, 저장 미확인은 동일 명령과 실제 조회로 확정한다. 이미지1:1/450:276 중앙 조정·용도/소유권·참조중삭제금지·실제파일/임대후예산반환·정리재시도를 적용한다. 구체한도/출처/동작은 docs/20과 실제 migration을 따른다.

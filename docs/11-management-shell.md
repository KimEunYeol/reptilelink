관리 헤더/푸터의 로고는 제공된 관리 PC PNG의 로고 영역만 추출했다. 좌표·원본/결과 해시는 `public/brand/README.md`에 기록했다. 다른 화면의 수제 Brand/Gecko는 교체한 것으로 주장하지 않는다. 캡처의 개체 사진 중 도마뱀 그림은 기존 테스트 업로드 파일이며 새 브랜드나 승인된 원본 사진이 아니다.

기존 페이지 공개/비공개 전환과 실제 공개 페이지 열기는 복사 영역 아래에 작은 텍스트 행으로 배치한다. 원본의 텍스트 버튼/초록·회색 패턴을 조합해 기존 조작과 상태를 보존한 최소 확장이다. 비공개 주소 복사는 F-07대로 먼저 공개 안내를 표시한다. 로컬 주소는 localhost이며 운영 HTTPS 주소 검증을 의미하지 않는다. 목록의 미저장/미확인 상태에 따른 공개 전환·로그아웃 잠금과 이동 안내도 유지한다.

## 남은 차이

- 링크·일정·디자인 수정·통계/알림은 아직 기능이 없어 disabled 및 준비 중 접근성 텍스트를 제공한다. 실제 알림이 없으므로 원본의 알림 점을 만들지 않는다.
- 기본 정보 폼 내부는 기존 브리더 프로필 폼이다. 자체 비밀번호·전화/SMS·광고 수신 UI를 추가하지 않는다(D-01·무료 운영 결정). 프로필/SNS 폼 원본 정비는 별도 범위다. 실제 사진 사용량은 이 화면 하단으로 옮겼다.
- 원본의 회사/연락처/SNS/TEAM770과 미구현 공지/About은 복사하지 않았다. 실제 운영 자료가 없어 푸터는 로고·안내 링크·저작권·한국어 표시 패턴만 사용한다. 푸터의 모든 항목/높이를 동일하게 완료한 것은 아니다.
- 정확한 폰트 파일과 더 높은 해상도 로고 벡터는 없다. 제공 PNG의 로고 픽셀을 사용하며 외부 배포 권리 확인 완료로 표시하지 않는다.
- 메인·로그인·공개 페이지/Worker의 외형, 등록 폼·사진/개체 삭제·성장 등은 별도다. 상위 #2는 계속 열린 상태로 유지한다.

## 확인 방법과 증거

로컬 백엔드/앱/Worker 실행 후 `npm run verify`. DB 초기화·새 마이그레이션·외부 웹 콘솔·배포·유료 작업은 없다.

- `tests/e2e/management-shell.spec.ts`: 7개 폭의 메뉴/전체 페이지 넘침·목록 폭·실제 로고 로드·푸터, 키보드로 기본 정보 진입/활성 탭, 실제 클립보드/새 탭·비공개 복사 안내·공개 전환·초안 잠금·로그아웃, 빈 목록/최대 주소 길이.
- 빈 목록/긴 주소는 응답만 바꾼 표시 fixture이며 DB에 합성 주소를 저장하거나 기존 개체를 삭제하지 않는다. 공유 테스트는 자신의 프로필 공개 상태를 복원하며 목록 적용 요청은 보내지 않는다.
- 기존 편집/목록 이동 회귀의 메뉴 이름과 첫 흐름의 제목 선택자를 변경된 실제 문구에 맞췄다. 새 셸 테스트 첫 실행의 두 실패는 기존 안내를 dialog/다른 문구로 잘못 선택한 테스트를 수정한 뒤 재실행해 통과했다.
- `artifacts/shell-8/before-{390,1440}.png`: 변경 전 비교.
- `top-{320,360,390,450,768,1440,1920}.png`, `footer-{동일폭}.png`, `top-overview.png`, `footer-overview.png`: 실제 캡처와 직접 검토.
- `basic-320.png`, `empty-long-320.png`: 기본 정보·활성 메뉴 및 응답 fixture 빈 목록/긴 주소 비교.

새 셸 브라우저3개와 기존 편집8개가 통과했다. 복사 live 영역과 저장 status의 선택 충돌을 분리하고 메뉴의 offset 계산을 해당 스크롤 컨테이너 기준으로 보완했다. Worker의 정적 로고도 원본 추출 결과와 동일한 바이트 해시인지 확인했다. 전체 npm run verify에서 production build+175개(하네스12·단위11·DB121·미디어8·E2E23)가 통과했다. 기록 갱신 후 최종 파일 상태를 다시 verify하며 task8·로컬 보고서·PR로 연결한다. 기존 번들500kB 초과 경고는 유지된다. 테스트/픽셀 검사만으로 디자인 의미 일치를 판정하지 않았으며, 원본과 실제 캡처를 직접 열어 범위 내 패턴을 대조했다.

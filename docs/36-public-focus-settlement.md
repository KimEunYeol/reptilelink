# 공개 상세 닫기 초점 복원 (#58)

기준 main24d4027908856a0ddaf5ad5823e5c7e61604bf05. 사진복구 PR57 최종 검증에서 기존 공개 카드6 복원 실패를 발견해 별도 이슈/최신main 브랜치로 분리했다. PR57의 리뷰수정은 stash로 보존하고 실제적용된 DB마이그레이션20261029220106도 보존한다. 이 UI 변경에서 DB변경이나 shadow동일 주장을 하지 않는다.

## 관측과 변경

기본코드 그대로 새 QA 공개개체7개에서 root→2페이지→개체7/Escape→직접개체6/닫기를 반복했다. 네 번째 반복에서 초기 반응조회가 카드를 disabled로 바꾼 뒤 focus()가 실행되고, 복원완료표시 때문에 조회종료/잠금해제 뒤 다시 시도하지 않는 것을 native focus/disabled 이벤트로 기록했다. `.local/focus58-before-repro.json`과 로그는 무시되는 로컬 증거다. 테스트는 타이밍을 바꾸지 않고 native 호출만 관측했고 실제 QA를 탈퇴/정리했다.

경로별 ProfileLikes가 최초 조회의 성공 또는 실패 정리를 알린 뒤 현재 경로의 목록복원을 허용한다. 로딩 완료와 초기잠금 완료를 구별하고 다른경로의 완료를 재사용하지 않는다. 경로 재조회 시작마다 완료표시를 비워 상세의 최초조회 종료전 빠른 닫기에서도 이전목록의 완료표시가 재사용되지 않게 한다. rAF 시점에서도 카드가 활성상태인지와 document.activeElement를 확인한 뒤 완료표시한다. 이후좋아요 조작은 이미복원한 위치의 초점을 다시 가져가지 않는다. 비공개/오류/댓글·알수없는좋아요 요청 잠금은 바꾸지 않는다.

공통40의 지연응답 테스트도 실제 전송완료 장벽으로 정리했다. 첫 실제응답만 보류하고 새계정 조회는 통과시킨다. 늦은 unread1 응답의 response.finished와 두 프레임을 확인한 다음 최신0이 유지되는지 검증한다. 처리중 route를 unrouteAll로 닫거나 오류를 무시하지 않는다. 메인이미지 검사는 모든 실제 img decode 뒤 정확한 handler를 해제한다. 제품 Auth/알림 코드는 바꾸지 않았다. 이 두 지연응답 검사는40회 연속 통과했고, 수정된 메인이미지 배치 검사도 통과했다.

## 디자인과 검증 범위

원본 `design/링크페이지.png`, `링크페이지-m.png`, `링크페이지-m-1.png`와 전체보드 PC설명(0,8400,5000,1000)의 모바일동일본문/상세팝업을 다시 확인했다. 원본의 좁은 공개본문/5카드/닫기와 기존 초점패턴을 유지하며 새 그림·레이아웃·문구를 만들지 않는다. 기존 source39 캡처/7폭·키보드/직접URL/Back/스크롤/dirty댓글/알수없는좋아요·Worker/noJS 회귀를 그대로 검사한다. 원본폰트·권리/운영자료와 외부콘솔·배포 검증은 범위 밖이다.

추가2개 브라우저 검사는 직접 상세 닫기 후 최초 실제 반응응답을 보류하고, 성공/503실패 두 경우 모두 조회중 카드잠금과 완료후 카드6초점을 확인한다. 실패후재조회/실제좋아요쓰기가 이전카드로 초점을 빼앗지 않는지 확인한다. 첫 검사 작성 때 disabled 또는 제거된 버튼에 초점이 유지된다는 잘못된 기대를 발견해, 이 이슈의 계약인 카드로 초점재강탈이 없다는 검사로 수정했다. 기존 disabled 처리를 바꾸거나 실패를 감추지 않는다.

수정후 같은 관측기로60회 반복해 초점실패0건을 확인했다. 관련17개중공개10/공통6은통과했고 메인이미지1개는측정중root가비어 실패했다. 파일고정뒤 해당이미지검사5회는모두통과했다. 전체검증 중에는 문서를포함한 추적파일/서버빌드를 바꾸지 않는다. 이 실패를 전체성공으로 표시하지 않는다.
